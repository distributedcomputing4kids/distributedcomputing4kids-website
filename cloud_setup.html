☁️ Setup in the cloud

Borrow a cluster in the cloud

Lots of companies will rent you a whole cluster of computers with a Spark notebook already set up on it, and several will let you use a small one for free. This page walks a grown-up helper through the sign-up. 🌐

Grown-ups: read this part first. 🛑 Most cloud accounts ask for a credit card, and most of them can charge real money if a cluster gets left switched on. So:

  • An adult should own the account and enter the card. Cloud providers require you to be an adult to sign up anyway.
  • Set a budget alert while you're signing up — every provider on this page has one — so you get an email long before anything surprising happens.
  • Shut the cluster down when you're finished. This is the one that actually costs people money. See the tidying up checklist.
  • Don't want to hand over a card at all? Start with Databricks Free Edition — no card, no timer, no way to run up a bill.

Which one should we pick? 🤔

Holden has worked at or with Google Cloud, Amazon AWS, Microsoft Azure, IBM Cloud, Snowflake, and Databricks, and they will all happily run the code from this book. The buttons live in different places and everybody uses slightly different words for the same things, but underneath it's the same Spark.

Fair warning about button names 🔀 Cloud companies redesign their websites constantly — often several times a year. The steps below describe what you're looking for and roughly where it lives, but if a button has moved or been renamed, that's the website changing, not you being lost. Searching the provider's own docs for the words in bold usually lands you in the right place.

🧱 Databricks

Databricks was started by the people who created Spark, and their free tier is the gentlest way to get a Spark notebook. No credit card, and no cluster to remember to turn off.

  1. Go to databricks.com/learn/free-edition and sign up for Databricks Free Edition. (You may still see this called Community Edition in older books and blog posts — same idea, newer name.)
  2. Confirm your email address and log in.
  3. In the left sidebar click New → Notebook.
  4. Make sure the language selector at the top of the notebook says Python.
  5. Type spark.range(1000000).filter("id % 7 == 0").count() into the first cell and press Shift+Enter.

The compute starts itself the first time you run a cell — that can take a minute — and then you should see 142858.

Did you notice? ✨ You never typed SparkSession.builder. On Databricks the variable spark already exists, ready to go, in every notebook. Most cloud notebooks do this for you.

Free Edition is capped in size and idles itself out when you stop using it, which is exactly what we want. If you outgrow it, Databricks also offers a full trial that runs inside an AWS, Azure, or Google Cloud account — that one can cost money, so read the tidying up section first.

🔷 Google Cloud

Google Cloud's Spark service is called Dataproc. New accounts get a free trial credit, and a card is required to prove you're a human — Google says it won't charge you when the trial ends unless you choose to upgrade.

  1. Sign up at cloud.google.com/free with a Google account.
  2. Create a project — think of it as a labelled box that holds everything you make. Call it something like dc4k.
  3. Set a budget alert: search the console for Billing → Budgets & alerts, and make a budget for a small amount like $5 so you get an email if something you forgot about is still running.
  4. Search the console's top search bar for Dataproc and enable the API when it asks.
  5. The friendliest option is Serverless for Apache Spark (older docs call this "Dataproc Serverless"): choose to create an interactive session, or open BigQuery Studio and start a notebook with a Spark session attached. Serverless means there's no cluster sitting around costing money between uses.
  6. If you'd rather have a classic cluster, use Dataproc → Create cluster, pick the smallest machine type offered, tick Jupyter under optional components, and — importantly — set scheduled deletion so the cluster switches itself off after an hour or two of idleness.

The five-minute shortcut 🏃 Google Colab is free, needs only a Google account, and gives you a Python notebook in your browser. Run !pip install pyspark in the first cell and you can do every exercise in the book on Colab's single machine — the same as installing Spark on your own computer, but with nothing to install. It's not a real cluster, but the code is identical.

If Spark complains about the Java version, run !apt-get -qq install -y openjdk-17-jdk-headless first and try again.

📦 Amazon AWS

Amazon's Spark service is EMR — Elastic MapReduce, named after MapReduce, which was Spark's ancestor. AWS has the most steps of any provider here, and EMR is not part of the AWS free tier, so keep an eye on the meter.

  1. Sign up at aws.amazon.com/free. You'll need a card and a phone number.
  2. Turn on a budget straight away: search for Billing and Cost Management → Budgets, and create a small monthly budget with an email alert.
  3. Pick a region in the top-right corner — somewhere near you — and stick with it. Things you make in one region are invisible in the others, which confuses absolutely everybody at least once.
  4. Search for EMR, then choose EMR Serverless and create an application with the Spark option. Serverless is the right choice for us: it bills for the time your work is actually running rather than for a cluster sitting idle. Leave the "pre-initialized capacity" setting alone — that option keeps machines warm and ready, which also means it keeps them billing.
  5. For a notebook, open EMR Studio and create a Workspace, then attach it to your serverless application. Alternatively, SageMaker Studio notebooks and AWS Glue interactive sessions both give you PySpark with less clicking.
  6. Some steps ask you to create an IAM role or an S3 bucket. Accept the defaults it offers — those are the permission slip and the storage locker, and AWS will make sensible ones for you.

Watch out for classic clusters ⚠️ If you create a classic EMR cluster rather than serverless, it charges for every hour it exists, whether or not you're using it. Terminate it the moment you're done, and check back the next day to be sure it's really gone.

🟦 Microsoft Azure

Azure has more than one Spark: Microsoft Fabric (the current recommendation, with Spark notebooks built in), Azure Synapse Analytics Spark pools, and Azure Databricks, which is Databricks living inside Azure.

  1. The quickest path is Microsoft Fabric: sign in with a Microsoft account and start the Fabric trial. The trial capacity doesn't need a credit card, but it usually does need a work or school email address rather than a personal Outlook or Hotmail one — which makes this a great option if a parent can sign up through their workplace, and an awkward one otherwise.
  2. In Fabric, create a workspace, then inside it create a Notebook. Fabric notebooks are PySpark notebooks with spark already defined, so run spark.range(1000000).filter("id % 7 == 0").count() and you're off.
  3. For the full cloud instead, sign up at azure.microsoft.com/free (card required, comes with a trial credit), then search the portal for Azure Databricks and create a workspace. From there it looks just like the Databricks steps above.
  4. Set a spending cap or budget under Cost Management + Billing. Azure free accounts have a genuine spending limit you can leave switched on, which is a lovely safety net.

🔵 IBM Cloud

IBM's notebook environment is part of watsonx.ai Studio — you'll see it called Watson Studio in anything written before 2024 — and its Spark cluster service is IBM Analytics Engine. IBM's free "Lite" plans don't need a credit card.

  1. Sign up at cloud.ibm.com/registration and verify your email.
  2. From the catalog, add watsonx.ai Studio and choose the Lite plan. Lite plans are free and simply stop when you've used up the month's allowance — they don't bill you.
  3. Create a project, which is IBM's box for holding notebooks and data. Some projects ask you to associate a Cloud Object Storage instance; pick the Lite plan for that too.
  4. In the project, add a new asset of type Notebook, and when it asks for the runtime, pick one whose name includes Spark.
  5. Run spark.range(1000000).filter("id % 7 == 0").count() in the first cell.

Lite runtimes have a monthly hour budget and stop your notebook when it's been idle for a while. That's a feature, not a bug — nothing can run up a bill in the background.

❄️ Snowflake

Snowflake gives you a 30-day trial with a chunk of free credits and no credit card, and it has notebooks built in. One thing to know up front: Snowflake's own DataFrame library is called Snowpark. It was deliberately designed to look like Spark, so most of the code in this book reads the same — but it isn't literally Spark, so a few things are spelled differently.

  1. Sign up at signup.snowflake.com. Any cloud provider and region will do.
  2. Log into Snowsight (the web interface) and choose Projects → Notebooks → + Notebook.
  3. Pick the smallest warehouse offered. A Snowflake warehouse is its word for the cluster doing the work; it auto-suspends when you stop typing, which keeps the trial credits from evaporating.
  4. To use Snowpark, start your notebook with: 
    from snowflake.snowpark.context import get_active_session

session = get_active_session()
session.range(1000000).filter("id % 7 = 0").count()
  5. If you'd rather run genuine PySpark code against Snowflake, look up Snowpark Connect for Spark in their docs — it accepts real Spark DataFrame code and runs it on Snowflake's engine.

Our suggestion 💡 Snowflake is a great thing to have seen, but if this is your first cluster and you want the book's examples to match character-for-character, start with Databricks Free Edition and come back to Snowflake afterwards.

Does it work? The same test everywhere 🧪

Whichever provider you picked, run this in the first cell of the notebook:

spark.range(1000000).filter("id % 7 == 0").count()

If the answer is 142858, you have a working Spark cluster and you're ready for the book. 🎉

If it complains that spark is undefined, the notebook probably isn't a Spark notebook — or it's still starting up. Try adding this above it:

from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("dc4k").getOrCreate()

If that fails too, the notebook is a plain Python notebook. Either pick a Spark runtime when you create the notebook, or run !pip install pyspark first — that gives you a one-machine Spark, which is plenty for the exercises.

Tidying up — the important bit 🧹

Cloud computers keep charging while they're switched on, even if nobody is looking at them. Make this a habit at the end of every session:

  • Databricks Free Edition, IBM Lite, Snowflake trial, Colab, Fabric trial: nothing to do. They stop themselves and can't bill you.
  • Any cluster you created by hand — a Dataproc cluster, EMR cluster, Synapse pool, or Databricks trial cluster — needs to be deleted or terminated. Not "stop the notebook": the cluster itself.
  • Check the bill the next day. Open the billing page and look at the current month's charges. If it says a few cents, or nothing, you're fine. This thirty-second check is how you catch a forgotten cluster before it matters.
  • Serverless options (Dataproc Serverless, EMR Serverless, Databricks serverless) only bill while something is actually running, which is exactly why we recommended them.
  • Done for good? Close the account, or at least remove the payment method. Every provider on this page lets you do that from the billing page.

When things go wrong 🔧

The sign-up won't accept the credit card
Providers usually put a small temporary hold (about $1) on the card to check it's real, and some prepaid and virtual cards get rejected for this. Try a different card, or use one of the no-card options: Databricks Free Edition, IBM Lite, or Snowflake's trial.
"Quota exceeded" or "insufficient capacity" when starting a cluster
New accounts start with low limits, and a region can genuinely be full. Ask for a smaller cluster (fewer machines, smaller machine type), or switch to a different region. Both are normal, and neither is your fault.
The cluster takes ages to start
Five minutes is normal for a real cluster — the provider is finding computers for you, switching them on, and installing Spark on each one. Serverless options usually start in under a minute.
A permissions or "access denied" error
Cloud accounts are strict about who is allowed to do what, and the person who made the account has to grant permissions to everybody else — including, sometimes, to themselves. Sign in as the account owner and accept the default role the wizard offers.
The notebook can't find your data file
Cloud clusters can't see the files on your laptop. Upload the file to the provider's storage first (S3, Cloud Storage, ADLS, Cloud Object Storage, or the notebook's own file browser), and use the path it gives you.
We got a bill! 😱
It happens, and it's usually a forgotten cluster. Delete anything still running, then contact the provider's support — all of these companies have a history of forgiving first-time accidental charges, especially for people who are learning.
This is all too much
Completely reasonable. Try Google Colab with !pip install pyspark, or install Spark on your own computer. The book works fine on one machine — a cluster just makes it more exciting.
