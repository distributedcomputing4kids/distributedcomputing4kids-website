💻 Setup on your own computer

Get Spark and Python running on your computer

You'll want a Spark and Python notebook to follow along with the book. Installing Spark has a lot of steps, so grab someone to help you with this part — a grown-up, a big sibling, a friend. It's much more fun with company. 🤝

First things first: you need an actual computer for this page. 🖥️ A Mac, a Windows PC, or a Linux machine — something with a keyboard, a screen, and a terminal you can type commands into. Everything on this page happens by typing commands, so a phone or tablet won't work.

  • iPad, iPhone, or an Android phone or tablet? You can't install Spark on these — Apple and Google don't let apps install other programs like this. That is not a you problem, it's just how those devices work. Head to the cloud notebook page instead: it runs in a web browser, so a tablet with a keyboard works fine.
  • Chromebook? Most can do it, but you have to switch on the Linux feature first — open Settings and search for "Linux development environment", turn it on, then open the Terminal app it gives you and follow the Linux instructions below. If your Chromebook is a small or older one, the cloud will be much happier.

Helpers: please don't feel bad if you get stuck. 💛 Installing Spark really does have many steps, and even people who do this for a living hit weird errors. Getting stuck is completely normal and it does not mean you did anything wrong.

If this page starts to feel like a fight, just stop and use a cloud notebook instead. That takes about ten minutes, and the code in the book is identical either way.

What are we installing, and why? 🧩

Spark is the program that splits a big job up across lots of computers — the same trick as getting every classroom to count their own results instead of one poor person counting the whole school district. To run it on one computer we need three things:

  • Python 🐍 — the language we write our programs in. We'll install it with conda, which keeps this project's Python in its own tidy box, separate from anything else on the computer.
  • Java ☕ — Spark itself is written in Java and Scala, so even though we type Python, Java has to be there underneath. This is the step people forget most often, and it causes the most confusing error messages.
  • PySpark and JupyterLab — PySpark is the Python flavour of Spark, and JupyterLab is the notebook where we type code and see answers appear. We use PySpark 4.2 throughout the book, so that's the version we ask for.

Plan for about 20–40 minutes, most of it waiting for downloads. You'll need a Mac, Windows, or Linux computer with roughly 5 GB of free disk space and an internet connection.

Pick your computer 👇

🍎 Mac Miniforge, or Homebrew if you already have it 🐧 Linux Miniforge, or your own package manager 🪟 Windows One extra fiddly bit at the end — we'll walk you through it

Then everybody meets back up at testing that it worked and starting the notebook.

🍎 Instructions for Mac

Open the Terminal app: press ⌘+Space, type "Terminal", press Enter. Commands go in that black-and-white window — type one line at a time and press Enter after each one.

Step 1: install conda

We recommend Miniforge, a small, free, no-strings-attached version of conda.

If you already have Homebrew (type brew --version to find out):

brew install --cask miniforge

If you don't have Homebrew, that's fine — you don't need it. Download the Miniforge installer for macOS from conda-forge.org/download. To know which one to pick, click the Apple menu → About This Mac: if the chip is called something like "Apple M1" or "M4", choose arm64 (Apple Silicon); if it says Intel, choose x86_64. Then run the file you downloaded:

bash ~/Downloads/Miniforge3-MacOSX-arm64.sh

Say yes when it asks whether to initialize conda. When it finishes, close Terminal and open it again — conda isn't switched on until you do. You'll know it worked when the prompt starts with (base).

Step 2: make a home for the project

This creates a little sandbox called dc4k with its own Python and its own Java, so nothing we do here can break anything else on the computer.

conda create -n dc4k -c conda-forge python=3.12 openjdk=17
conda activate dc4k

Say y when it asks to proceed. The prompt should change from (base) to (dc4k).

Remember this one line 📌 conda activate dc4k — every new Terminal window starts out forgetful, so you have to type that before running Spark. It's the single most common reason things "suddenly stop working" tomorrow.

Step 3: install PySpark and the notebook

pip install --upgrade "pyspark==4.2.*" jupyterlab pandas

That installs PySpark 4.2. It's a biggish download — a few hundred megabytes — so this is an excellent moment to go get a snack. 🍪

Now skip down to testing that it worked.

Homebrew-only alternative 🍺 If you'd rather not use conda at all, brew install openjdk@17 plus brew install python also works. You'll then need to link the Java install so Spark can find it — Homebrew prints the exact sudo ln -sfn … command to run when it finishes, so copy that. We still suggest conda, because it puts Python and Java in the same tidy box and doesn't touch the rest of your Mac.

🐧 Instructions for Linux

Open a terminal — on most systems Ctrl+Alt+T does it.

Step 1: install conda

curl -L -O "https://github.com/conda-forge/miniforge/releases/latest/download/Miniforge3-$(uname)-$(uname -m).sh"
bash Miniforge3-$(uname)-$(uname -m).sh

Say yes when it offers to initialize conda, then close the terminal and open a new one. The prompt should now start with (base).

Step 2: make a home for the project

conda create -n dc4k -c conda-forge python=3.12 openjdk=17
conda activate dc4k

The prompt changes from (base) to (dc4k). You'll need to type conda activate dc4k in every new terminal window.

Step 3: install PySpark and the notebook

pip install --upgrade "pyspark==4.2.*" jupyterlab pandas

Prefer your own package manager? 📦 That works too. Install a JDK and pip with sudo apt install openjdk-17-jdk python3-pip python3-venv (Debian/Ubuntu), sudo dnf install java-17-openjdk-devel python3-pip (Fedora), or sudo pacman -S jdk17-openjdk python-pip (Arch), then use a plain virtual environment:

python3 -m venv ~/dc4k
source ~/dc4k/bin/activate
pip install --upgrade "pyspark==4.2.*" jupyterlab pandas

Just don't pip install straight into the system Python — newer distributions block that on purpose, and they're right to.

🪟 Instructions for Windows

A shortcut worth knowing about 🧭 Spark was born on Linux and is happiest there, so the smoothest path on Windows 10 or 11 is often the Windows Subsystem for Linux. Open PowerShell as Administrator, run wsl --install, restart the computer, then open the "Ubuntu" app from the Start menu and follow the Linux instructions inside it.

If that sounds like too much, the native Windows steps below work fine — they just have one extra fiddly bit at the end.

Step 1: install conda

Download the Miniforge installer for Windows from conda-forge.org/download and run it. Accept the defaults, and install it "Just Me" into a path with no spaces in it — the default, C:\Users\yourname\miniforge3, is perfect. Spaces in paths confuse Spark.

When it's done, open Miniforge Prompt from the Start menu. That's the window you'll use for everything below — not the regular Command Prompt or PowerShell, because conda is only switched on inside this one.

Step 2: make a home for the project

conda create -n dc4k -c conda-forge python=3.12 openjdk=17
conda activate dc4k

Say y when asked. The prompt should change to say (dc4k).

Step 3: install PySpark and the notebook

pip install --upgrade "pyspark==4.2.*" jupyterlab pandas

Step 4: the fiddly Windows bit (winutils)

Spark expects a couple of small Hadoop helper files that only exist on Windows. Without them Spark often still runs, but it prints scary red errors and saving files fails. Here's how to give it what it wants:

  1. Make a folder called C:\hadoop\bin.
  2. Download winutils.exe and hadoop.dll from the cdarlint/winutils collection on GitHub. Pick the folder with the highest version number available, open its bin folder, and download those two files. The version doesn't have to match Spark's exactly — any recent Hadoop 3 build works.
  3. Put both files in C:\hadoop\bin.
  4. Tell Windows where they are. Press Start, type "environment variables", and choose Edit the system environment variables → Environment Variables. Under "User variables" click New and add a variable named HADOOP_HOME with the value C:\hadoop. Then find Path in that same list, click Edit → New, and add C:\hadoop\bin.
  5. Close the Miniforge Prompt and open a new one so it notices the change. Don't forget conda activate dc4k again.

Heads up ⚠️ Only download these files from a source you trust, and never run an installer for them that asks for administrator rights — these are just two small files that get copied into a folder, nothing more.

Testing that it worked (everyone) 🧪

In your terminal, with (dc4k) showing in the prompt, type:

pyspark --version

You should see the word Spark drawn out big using slashes and underscores (that's Spark showing off), a version number starting with 4.2, and a line naming the Java it found. If you see that, Java and Spark have found each other and the hard part is over. 🎉

Version 4.2, or: 42 with a dot in it 🌌 Which means we are working with the Spark release that answers life, the universe, and everything. We pin the book to 4.2 on purpose, so the version on your screen matches the version in the chapters instead of drifting every few months. If you ever need to check later, pyspark --version is how.

Now let's actually compute something. Start the interactive shell:

pyspark

Wait for the >>> prompt. It can take 20 seconds and print some warnings along the way — warnings are fine, that's just Spark talking to itself. Just above the prompt it should say SparkSession available as 'spark', which is Spark handing you a ready-made variable called spark. Then type:

spark.range(1000000).filter("id % 7 == 0").count()

It should think for a moment and answer 142858.

Where does that number come from? There are 142,857 multiples of seven under a million — and 142857 × 7 = 999999, which is one of the tidiest facts in arithmetic — and then zero counts too, because zero divides by everything. So: 142,858.

You just did distributed computing! 🏆 That was Spark splitting a million numbers across all the cores in your computer and adding up the answers — the exact same trick it uses to split work across a thousand computers. Your gnomes would be proud. Type exit() to quit.

Starting the notebook (everyone) 📓

The book uses notebooks, which are much nicer than the shell: you can edit, re-run, and keep your work. In the terminal:

conda activate dc4k
jupyter lab

Your web browser opens with JupyterLab in it. Click Python 3 under "Notebook" to make a new one. In the first cell, type this and press Shift+Enter:

from pyspark.sql import SparkSession

spark = SparkSession.builder.appName("dc4k").getOrCreate()
spark.range(1000000).filter("id % 7 == 0").count()

You should get 142858 again, this time inside the notebook. That's it — you're ready for the book! 🚀

Secret bonus: watch Spark work 👀 While a notebook is running, open localhost:4040 in another browser tab to see Spark's own dashboard. It shows the work being chopped into pieces in real time, and it is genuinely fun to watch.

To stop the notebook, go back to the terminal and press Ctrl+C twice.

When things go wrong 🔧

Almost everyone hits at least one of these. Nothing on this list means the computer is broken.

conda: command not found (or "not recognized")
The installer finished but the terminal hasn't noticed yet. Close every terminal window and open a fresh one. On Windows, use Miniforge Prompt from the Start menu, not Command Prompt or PowerShell.
JAVA_HOME is not set, or Unable to locate a Java Runtime
Java isn't installed, or Spark can't see it. Inside your conda environment, run conda install -c conda-forge openjdk=17 and try again. Check what you've got with java -version — Spark 4.2 runs on Java 17, 21, or 25, and we install 17.
UnsupportedClassVersionError, or a complaint about "class file version"
The Java that's installed is too old for this version of Spark. Install a newer one: conda install -c conda-forge openjdk=17.
TypeError: 'JavaPackage' object is not callable
Almost always the same problem wearing a disguise — Python found PySpark but not a usable Java. Fix Java as above.
A very long red Py4JJavaError wall of text
Don't panic, and don't read all of it. Scroll to the top of the message: the first line or two is the real cause, and everything below it is Spark explaining where it was standing when things went wrong.
macOS: "Do you want the application to accept incoming network connections?"
Click Allow. Spark's pieces talk to each other over the network even when they're all on the one computer. Nothing is leaving your machine.
Windows: errors mentioning winutils, NativeIO, or UnsatisfiedLinkError
That's step 4. Check that both files really are in C:\hadoop\bin, that HADOOP_HOME is set to C:\hadoop (with no \bin on the end), and that you opened a brand new prompt afterwards.
Address already in use, or port 4040 is busy
An older Spark is still running somewhere. Close other notebooks and terminals — or just ignore it, because Spark will quietly move itself to port 4041.
The notebook can't find PySpark, even though you installed it
The notebook is probably running from a different Python. Quit it, run conda activate dc4k, and start jupyter lab again from that same window. Inside a notebook, import sys; print(sys.executable) should show a path with dc4k in it.
Everything is just… slow
On one computer, Spark spends a lot of effort organizing work that a plain Python loop would finish instantly. That's expected! Spark's superpower only shows up when the data is bigger than one machine. We use a small computer here so we can learn the ideas without needing a warehouse full of servers.
Nothing on this list helps 😭
Genuinely, this is fine, and it is not your fault. Use a cloud notebook instead — the code in the book is identical either way, and you'll be up and running in about ten minutes.
